# MVP 실험실

[English](../en/mvp.md)

## 구현 범위

모듈별 MVP는 **mon_dog(Labrador mutt)**에 개체별 실험용 훈련 스위치를 적용한다. 기본 능력치는 올리지 않는다. 미훈련 개는 DoGS 공격 두 개만 비활성화한 뒤 기존 AI를 사용한다. 완성된 동료 AI가 아니라 실험용 구현이다.

NORMAL의 ASSIST는 적이 플레이어와 인접할 때, INTERCEPT는 플레이어 3타일 이내일 때, 그 외에는 SKIRMISH로 분류한다. 적 주변의 밀집도를 표적 점수에 반영한다. 이는 임시 휴리스틱이다. ASSIST는 플레이어가 실제 상대 중인 적을 식별하지 않고, INTERCEPT도 접근 속도를 추적하지 않는다.

체력이 절반 이하이거나 인접 적이 2개 이상, 3타일 내 적이 4개 이상이면 공격보다 RETREAT가 우선한다. 플레이어와 6타일보다 멀거나 표적이 없으면 REGROUP이다. 이동은 인접한 빈 타일 중 위험을 줄이는 타일을 고르며 엔진의 이동 비용·충돌 판정을 사용한다. 장기 경로 계획과 포위 예측은 없으며 벽·막다른 길에서 멈출 수 있다. 적절한 이동이 없으면 기다린다. 이동 구속, 탑승, 목줄·하네스, 기절, 진정 효과는 기존 엔진 처리에 맡긴다. 같은 층 8타일 내 보이는 적대 **몬스터**만 고려하며 적대 NPC는 아직 지원하지 않는다.

## 실험용 공격

| 공격 | 피해 | 비용 / 쿨다운 | 양의 피해를 준 뒤 효과 |
| --- | --- | --- | --- |
| Takedown | 타격 2 | 이동력 100 / 8턴 | downed 2턴 |
| Ankle Tear | 절단 4 | 이동력 100 / 8턴 | bleed 20턴, dogs_ankle_wound 10턴 |

Takedown은 크기·저항 규칙이 정해질 때까지 **mon_zombie**에만 허용한다. 자동 모드는 서 있는 일반 좀비에 Takedown, 그 외에는 Ankle Tear를 선택한다. Takedown 전용 모드에서 부적합한 표적이면 기다린다. 공격이 처리되었어도 회피·방어구 때문에 피해가 없을 수 있으므로 로그에 처리 여부, 실제 HP 피해, 효과 유무를 따로 기록한다. 엔진 면역은 그대로 적용하며 downed는 일어서기에 성공하면 일찍 끝날 수 있다.

전용 상처는 **속도 보너스 -20**을 적용한다. 20% 감소가 아니다. 최대 강도는 1, 지속 시간은 최대 10턴이다. 일반 근접 actor를 사용하는 이 시제품은 몬스터의 발목을 해부학적으로 지정하지 않는다. 넘어질 확률은 추가하지 않았다.

## 설치와 플레이 검사

Windows 저장소 루트에서 실행한다.

```powershell
.\scripts\Install-Mod.ps1 -GameDirectory ..\game_redhot
```

게임의 `mods/DoGS`를 저장소의 `mod` 폴더에 정션으로 연결한다. 관계없는 기존 대상이 있으면 교체하지 않는다. 코드·데이터 변경 뒤 게임을 재시작하고 별도 시험 월드에서 **DoGS — Dogs of Good Sense (MVP)**를 활성화한다. Lua API 2가 필요하며 2026-09-24 안정판은 검증에 사용하지 않았다.

1. 게임·디버그 기능으로 Labrador mutt를 생성하고 기존 방식으로 길들인다.
2. **action_menu → 기타 → DoGS laboratory**에서 개를 선택해 실험용 훈련을 켠다. 공격 모드와 선택적 행동 메시지도 여기서 설정한다. 리모컨 생성이나 수동 스냅샷은 필요 없다.
3. 열린 장소에서 일반 좀비를 대상으로 각 공격 모드를 검사한다. 모드 변경은 쿨다운을 초기화하지 않는다.
4. 개의 AI 실행 전후 상태 변화와 5턴마다의 상태, 주변 8타일 내 보이는 몬스터의 상태 변화를 자동 기록한다. 공격 표적은 공격 전후에, 이동 성공·실패는 발생 시 기록한다.
5. 미훈련 개, 낮은 HP, 적 무리, 장애물, 묶임·넘어짐, 저장 후 복원을 검사한다. 이는 실제 플레이 검사이며 로딩 성공으로 증명되지 않는다.

로그는 활성 사용자 디렉터리의 **config/debug.log**에 있다. `[DoGS]`를 검색한다. 기록이 없으면 게임의 INFO/LUA 로그 설정을 확인한다.

| 이벤트 | 의미 |
| --- | --- |
| load / finalize | 등록 / 로딩 완료 후 정의 검사 |
| selftest | 정책·모의 가드·자동 로그 검사 결과 |
| action | 전술 상태 변경, 선택적으로 게임 메시지 |
| move | 자동 이동 시작·도착 좌표, 비용, 후퇴 여부, 개체 ID |
| attack | 공격 처리 여부, 실제 피해, 효과, 쿨다운 |
| state | 자동 개체 상태: 식별자, 타입, 위치, 현재·최대 HP, HP 변화량, 속도, 우호·훈련 상태, 전술, 효과, 쿨다운, 이동력, 게임 턴 |
| move_blocked | 인접 이동 실패 |

같은 종류의 개도 지속 식별자로 구별한다. HP 변화량은 직전 관측 이후의 순변화이며 개별 피격 횟수나 피해 원인을 뜻하지 않는다. 실제 ID 저장·복원 검사는 남아 있다. 사라짐·사망과 보이지 않는 표적은 아직 추적하지 않는다. 기존 저장에 있는 리모컨은 호환성을 위해 작동하지만 기본 접근 방식은 action_menu다.

## 검증 결과

검사 환경은 Windows x64 MSVC redhot **2026-10-04-0345**, 커밋 `ef0eceda391d4d291b366e3bf2833b04c7342d72`다. Lua API 시그니처는 이 실행 파일에서 추출했다. 이전 소스 감사의 기준은 `e0e25e9d8b3cf0d3b663882a7faf5a44d8ace800`이며 두 리비전은 구분한다.

```powershell
.\scripts\Test-Mod.ps1 -GameDirectory ..\game_redhot
```

검사기는 별도 임시 사용자 디렉터리에서 `--check-mods DoGS`를 실행하고 stdout·stderr·debug.log를 보존한다. 종료 코드 0과 Lua 성공 표식을 확인한다. **통과:** 데이터·스크립트 로딩, 엔진 좌표 객체를 사용하는 정책 assertion 10개, 모의 몬스터를 사용하는 가드 assertion 8개와 자동 로그 assertion 6개, 로딩 완료 후 ID 유효성. 모의 검사는 실제 엔진 callback 호출·전투의 증명이 아니다.

**실제 플레이 검사 미완료:** 이동·지형 비용, 공격 명중·회피와 방어구·면역, 실제 미훈련 개의 첫 행동, 효과 처리·만료, 저장 후 복원, 다른 모드와의 호환성. LURE, 정식 훈련, 다른 견종, 본격적인 경로 탐색은 아직 구현하지 않았다. 실제 전투 성공을 주장하지 않는다.

## 파일 구성

런타임 callback에서는 `require`를 호출하지 않는다. BN은 로딩 종료 후 모드 전용 `package.path`를 비우므로 필요한 모듈은 로딩 단계에서 지역 참조로 확보한다. 회귀 검사는 `package.path=nil` 상태에서 메뉴 설정 처리와 공격 쿨다운 처리를 모의 개체로 호출하며 실패해도 기존 경로를 복원한다. 이는 실제 메뉴 선택·전투의 검증과는 구분한다. 자동 로그·callback assertion은 기존 4개에서 6개로 늘었다.

`mod/json/`은 개 override·효과·기존 진단 아이템 호환 정의를 담는다. `mod/lib/`는 설정·로그·정책·탐색·이동·공격·AI·진단·자동 로그를 나눈다. `mod/tests/`는 로딩 중 검사 fixture다. `preload.lua`에서 JSON 사용 전에 callback과 action_menu를 등록하며 `finalize.lua`에서 정의를 검사한다. 엔진 동작 근거는 [소스 감사](source-verification.md)를 참조한다.
